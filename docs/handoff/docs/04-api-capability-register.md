# API capability register

Prepared: 2026-10-19. This is an implementation planning register, not a claim of working integration. **No credentials, entitlements, customer projects, endpoint calls, or processing jobs were tested for this handoff.**

## Evidence labels

- **Documentation verified:** a readable official source supports the stated capability, at its stated level of detail.
- **Implementation inference:** an engineering proposal derived from those capabilities; it still requires implementation and testing.
- **Unverified:** current endpoint semantics, access, or behavior have not been established sufficiently for implementation.
- **Project tested:** a recorded, successful exercise using the intended identity and authorized project. No entry currently has this status.

Do not replace one label with another implicitly. An overview or sample is not an endpoint contract; an endpoint contract is not proof of entitlement; an accessible project is not proof that a given user can create an Issue.

The API count mentioned in the conversation is not a dependency. The Forma catalog distinguishes Forma APIs from Forma-related APIs and SDKs. Selecting services in Developer Hub does not grant every product capability, customer-project permission, separate SDK license, or billing entitlement. [S01]

## Required live-integration evidence record

For every adapter that moves beyond fixtures, record:

1. Official endpoint reference URL and date checked; current version, region, lifecycle status, and method/path.
2. Supported authentication context, exact scopes, app provisioning, and project-role prerequisites. A token alone is not evidence of record access.
3. Sanitized request/response shape and the test identity's role; never tokens, cookies, client secrets, signed URLs, or private keys.
4. Positive test, permission-denied test, pagination/rate-limit behavior, and supported retry/reconciliation behavior.
5. Project-tested status with date and result. A fixture or mocked adapter remains a fixture even if it resembles a production response.
6. For writes: the exact approval snapshot, remote identifier, completion or partial-completion status, and readback result.

If a dependency fails this gate, keep the local workflow runnable with explicit fixtures or a documented manual import. Report the blocked live capability precisely; do not silently claim success or broaden permissions.

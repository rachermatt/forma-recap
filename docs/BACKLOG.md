# Subsequent increments

The 0.2 pilot is one project, one location/floor and one trade package, across several capture dates. The concept deck's automatic progress/quantity ambitions are research, not implemented measurement. This backlog supersedes conflicting assumptions in the original handoff; the supplied deck and notes remain source material.

| Increment | Dependencies | Acceptance criteria |
| --- | --- | --- |
| Model revision impact | Authorized version/metadata reads; versioned external-ID crosswalk; changed/deleted geometry policy and representative version pairs. | New versions create a separate model reference. Classify unchanged, changed, deleted and unresolved associations. Flag affected findings for review. Historical findings, drafts, tasks and packets retain their exact original model version; no silent migration. A reviewer records any replacement association with provenance. |
| Collaborative review | Real identities, project access, permissions, assignment and conflict-resolution model; multi-user storage/concurrency. | Assign reviews and due dates. Two reviewers can retain independent positions on one element/capture. A resolution links both assessments and its rationale without overwriting either. Enforce permission and stale-write checks. |
| Schedule comparison | Activity/source-version import; explicit scope-to-activity mappings and calendars; planned dates and revision history. | Compare dated evidence coverage with mapped planned dates. Label possible deviation as requiring investigation. Unknown dates and unobservable work produce an evidence gap, never an asserted delay or zero progress. Preserve schedule version and mapping source. |
| Evidence search | Indexed exact model/version/element/location/date/state fields, access filters. Later: retrieval evaluation and citation checks for conversational answers. | First provide combined filters for location, element, capture date and assessment state, including unknown dates. Later answers link exact source capture, finding revision and model version; unsupported questions return insufficient evidence. |
| Turnover preparation | Asset/location register; required-document checklist; inspection/acceptance sources; gap ownership. Tandem API/entitlement investigation is separate. | Assemble an evidence index for each asset/location with required documents, inspection records and outstanding gaps. Readiness is checklist-based and never inferred from visible installation. Preserve missing/unknown documents. Prove Tandem permissions, object mapping and transfer semantics before an adapter. |
| Pilot measurement | Consented event collection, timing definition, reviewer assignments and explicit denominators. | Track review time, unresolved findings, recapture rate and frequency per scope/capture, and agreement between independent reviewers. Report sample sizes and missing events. Add AI correction/acceptance rates only when separately labeled suggestions exist; retain the original suggestion and human decision. |
| Processing visibility | Actual asynchronous processing services; durable job IDs, retry policy and cost/resource metering. | Show queued/running/succeeded/failed status and actionable failure reasons, bounded retries and source references. A retry cannot duplicate evidence. Resource usage is measured with units and source, with unknown usage explicitly unknown. No fake processing stages for a direct local import. |
| Reviewed quantity exchange | Versioned schema; consumer semantics; scope/unit vocabulary; independent authorization and approval policy; idempotency/acknowledgment. | Export contract includes quantity or null, unit, scope, reporting period, source, measurement method/basis, model version, evidence/finding refs, approval status/reviewer/reference and revision. Validate round trips, unknowns, unit mismatch and superseded approvals before connecting to cost control. No implicit certification/payment action. |
| Verified model viewing | Intended user's 3LO consent, project-bearing hub/project, readable model version and derivative URN, supported source format/viewable, region and permissions. | Read manifest/metadata, verify successful viewable, map external IDs to transient Viewer dbIds and highlight selected elements in the actual fixed model version. Test denied access and missing/failed derivatives. No synthetic fallback. Credentials/access/refresh tokens stay server-side; resolve a restricted Viewer authorization approach consistent with the product's token rule before exposing any viewer credential. |
| External Issue/RFI submission | Verify separate product endpoint, user/project permissions, issue subtype/RFI workflow, attachment upload/download and element/location linkage. | Local drafts stay local until an explicit Submit action. Use a stable idempotency key and persisted result to prevent duplicates. Confirm created record ID/URL and evidence links, including partial attachment failure. Never report success from sign-in or draft creation alone. Keep Issue and RFI capability checks separate. |
| 360 and other capture formats | Authorized sample media, orientation/calibration and metadata semantics, format-specific viewer and annotation coordinates. | Preserve original bytes/date precision; show panorama orientation and annotation viewpoint reproducibly; validate output packets. Do not treat a manual pin as registration. Unsupported files remain rejected by the initial raster importer. |

## Research milestones — evaluation required before product claims

| Research capability | Required dataset and evaluation | Gate for a pilot capability |
| --- | --- | --- |
| Automatic capture registration | Authorized multi-date imagery and surveyed camera/control-point poses spanning occlusion, lighting and device variation. Hold out projects/dates; evaluate positional/angular errors, failures and confidence calibration against ground truth. | Agree numeric accuracy and failure thresholds with the intended use before evaluation. Report errors by condition and an explicit rejection/abstention rate. Store method, model version, confidence and independent validation separately from manual associations. |
| Geometric comparison | Ground-truth as-designed/as-built geometry pairs, tolerances, known revisions and occluded regions; independently labeled deviations. | Predeclare tolerance, precision/recall and false-alarm thresholds per use. Demonstrate hidden areas stay unknown and design revisions are not mistaken for installation deviations. Require human validation. |
| Trade recognition | Permissioned labeled multi-trade images with mixed trades, occlusion, site/device variation and out-of-distribution cases. Separate training/validation/test projects. | Predeclare class-wise precision/recall, confidence calibration and abstention thresholds. Keep suggestions distinct from human findings and track corrections. |
| Installed-quantity estimation | Surveyed/manual ground-truth quantities with units, fixed scope/version, capture coverage, occlusion, independent measurement and acceptance references. | Predeclare allowable bias/error and coverage requirements by trade/unit. Test double counting across dates and partial visibility. No percent complete without a validated denominator/method. Human measurement approval remains a separate record. |

Numeric research success thresholds are deliberately **not yet agreed**. This is a dependency to resolve with the pilot team before collecting evaluation results; no capability is marked validated by a polished demo.

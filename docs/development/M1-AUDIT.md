### M1-specific gaps at `ee463ce`

- **FR-002 — partial.** The mixed-results cards already use saved findings, and absent findings remain unassessed. However, `FindingEditor` initializes its editable observation to `needs_review` without a clear saved-versus-draft summary or dirty indicator. Its fields and annotations are component-local; changing the capture, element, section or shell route can remount the editor and discard edits without a deliberate decision. API failures do not create server revisions, but recoverable draft state needs direct UI verification. No-op/repeated submissions must not be presented as new completed review work.
- **FR-003 — partial.** An explicit Apply interaction and server period filtering already exist. The editable dates and active response period need clearer separation. Baseline `ReconciliationWorkspace` refreshes an active result by calling `applyPeriod()` using the current edited date fields, so a later record refresh can accidentally apply pending dates. Invalid intervals must leave the previous valid result intact. Server filtering uses exact record reporting periods and dated observation boundaries; unknown capture dates stay explicit.
- **FR-004 — partial.** `App.tsx` repeats the same primary destinations in the sidebar and horizontal navigation. Workbench “Fixed packets” adds an extra stop before the real packet destination. Review log → element review already passes an exact capture/element pair, and task reassessment already selects its supplied capture/element. Most other selection/section/period state remains component-local; leaving/re-entering views can reset it. There is no established URL/history context contract to preserve, so M1 must introduce a compatible, explicit route/context policy and explain unavailable links instead of falling back to unrelated data.

## Smallest coherent M1 implementation and rollback

1. Keep persisted saved findings separate from editable values; identify Not assessed, last saved revision and pending changes. Confirm the returned exact capture/element/revision after saving. Guard navigation with a deliberate retain/discard/save decision and preserve failed edits without creating a success state.
2. Separate pending date inputs from the authoritative applied period. Refresh records against that applied period, retain it through the intended view transitions, and show all-period/no-match/error states without converting unknowns to zero. Do not alter comparability or record dates.
3. Use the existing primary shell navigation; keep genuine task tabs. Go directly to Evidence packets and retain authorized workspace/project/scope/capture/element/reference context in related actions and browser history. Explain stale or inaccessible links.
4. Run existing checks, focused state-transition checks and direct interface verification for AC-01/AC-04 plus relevant AC-02 persistence, navigation, keyboard and narrow-layout behavior. Inspect the saved result and failure recovery, not only a rendered form.

These changes require no database migration. Keep all historical assessment/media/packet rows unchanged. Roll back a defective M1 interface by reverting its source changes and rebuilding against the same databases; do not restore an old database over newer human work. Stop the affected change for lost edits, misleading saved/filter state, incorrect context/workspace routing or altered fixed snapshots. Retain local manual review and fixed exports while repairing the interface. The read-only hosted boundary must remain enforced independently of disabled controls.

# Increment 0.2 implementation contract

Preserve all 0.1 tables, routes, scope assessments, exports, branding and navigation. New element records never derive implicitly from historical scope assessments. Data stores are separate: `fixture-review.sqlite` uses existing synthetic sources; `local-review.sqlite` contains user photographs and manually configured references. Neither is an APS live integration. APP_MODE=live rejects these local endpoints. This contract includes the acceptance-gap follow-up; [the current walkthrough](ACCEPTANCE-WALKTHROUGH.md) records the saved demonstration and validation. Historical isolated QA remains in [INCREMENT-VALIDATION.md](INCREMENT-VALIDATION.md).

## Shared server interface

`server/review.ts` exports `createReviewStore({dbPath,uploadDir,workspace,legacyStore,syntheticImportPath?})`, workspace `fixture|local`. Return `{db, bootstrap, configure, saveFinding, findingHistory, getFindingRevision, saveTask, linkTaskEvidence, coverage, getCapture, getMedia, getDisplayMedia, importPhoto, createExport, getExport, close}`. Methods take one plain input object unless noted. Errors carry `status` 400/404/409. db is a server-only DatabaseSync for workflows.ts. No tokens or secrets in returned state.

`bootstrap()` returns `{schema_version:'0.2.0',workspace,data_mode,project,model,scope,captures,findings,finding_revisions,tasks,task_events,exports,legacy_assessments,reviewer,freshness_days}`. Findings contains current revisions; finding_revisions contains all. reviewer `{id,name}` is server-owned. Local reviewer identity is explicitly self-asserted. Fixture project/model/scope come from legacyStore.bootstrap(); its capture list combines preserved legacy captures with separately stored, trusted synthetic recapture imports. Local starts unconfigured.

`configure({project_name,location,trade,scope_name,model_id,model_version,elements:[{external_id,label}]})` configures one local project/floor/trade; reject changes once captures, findings or workflow records exist. Model and scope refs are manual/unverified. Model `{id,version_id,version_label,elements:[{external_id,label,zone_id}]}`. Scope `{scope_id,revision,trade,floor,name,zone_id,element_ids}`. Capture follows existing `{capture_id,title,media_url,capture_ref,placement}`; local adds source,location,original_filename,content_type,width,height. Capture ref retains unknown/date/timestamp precision without fabricated dates. Original URLs `/api/v2/{workspace}/media/{id}` and display URLs `/api/v2/{workspace}/media/{id}/display` are distinct. `getDisplayMedia(id)` returns `{body,contentType,source_sha256,display_sha256,method,width,height}`. Trusted SVG fixtures have verified, lossless PNG derivatives (`trusted_svg_lossless_png`); JPEG/PNG/WebP uploads pass through unchanged (`original_raster`). The originals remain immutable and available separately.

`saveFinding({capture_id,element_id,state,rationale,uncertainty_reason,evidence_quality,annotations,previous_revision_id,recapture_task_id?,resolves_task_id?})` uses current configured scope/model and original source hash. State `observed_installed|not_observed|needs_review`; quality `usable|limited|unusable`. Require uncertainty for states other than observed. Annotation `{id?,x,y,width,height,label}` uses normalized displayed image coordinates, top-left; validate bounds. Return finding `{finding_id,revision_id,revision,previous_revision_id,capture_ref,model_ref:{model_id,version_id,element_id},scope_ref,state,rationale,uncertainty_reason,evidence_quality,annotations,review:{reviewer_id,reviewed_at},alignment}`. Stable identity capture/scope/model-version/element, append-only revisions, optimistic concurrency. A subsequent task assessment stores `recapture_task_ref` with task ID, originating finding revision and exact source capture/model/scope references. Corrections retain this relationship when optional task input is omitted and cannot silently move to a different task. findingHistory(id) returns all revisions. getFindingRevision(id) and getCapture(id) return exact records or throw.

`saveTask({finding_revision_id,reason,required_viewpoint,assignee,due_date,before_concealment,concealment_date?})` creates an assigned task from a needs-review finding. It preserves the exact originating finding, capture, model version, scope and element. Task records retain legacy `status` (`open|awaiting_reassessment|closed`) alongside separate `capture_status` (`requested|completed`) and `review_status` (`pending_evidence|awaiting_reassessment|reassessed`). `linkTaskEvidence({task_id,capture_id})` requires different, nonidentical original media that do not predate known source dates/times. It records `evidence_supplied_at`, completes the capture request and leaves reassessment pending, without creating a finding or installation/acceptance/approval claim. `saveFinding` with `recapture_task_id` records explicit reassessment for the exact affected element/model/scope and supplied capture, including a still-unresolved state. It sets `latest_assessment_revision_id`, `latest_assessment_state` and `latest_assessment_evidence_quality`; the original finding remains unchanged. Legacy `resolves_task_id` remains compatible and requires usable, non-needs-review evidence to record its historical closure. Later corrections preserve that closure reference while updating the distinct latest human assessment. All task events append.

`coverage({as_of_date?,freshness_days?})` returns `{as_of_date,freshness_days,total_elements,counts,elements:[{element_id,label,status,finding?,capture_date?,reason}]}`; statuses usable/unresolved/outdated/no_evidence/date_unknown; unique elements across capture dates. Missing dates stay unknown. Scope assessments do not count as individual evidence. Not observed is not an installed quantity.

`importPhoto({filename,content_type,bytes_base64,title,source,location,date_precision,captured_date?,captured_at?,original_timezone?})` async. Local imports accept JPEG/PNG/WebP <=15MiB, validated decoder <=50MP; immutable original bytes/hash, upload timestamp server-generated. Date precision unknown/date/timestamp explicitly validated. No inferred EXIF date. Annotations remain separate. Never expose upload paths. Fixture import is disabled unless `syntheticImportPath` is configured server-side; then it accepts only PNG bytes with the exact bundled source hash and forces `synthetic_test` provenance/source labels. It cannot admit real photographs or arbitrary test images into the synthetic workspace.

`createExport(extra, {coverage_rule?:{as_of_date?,freshness_days?}})` stores immutable HTML+JSON including original media bytes/hashes, separately embedded display derivatives with their original-source hashes, all finding/task revisions, legacy context, the explicit coverage rule and supplied selected workflow snapshot. The visible report includes revision-specific annotations, recapture decision events and historical scope assessments. Original media and annotation data remain separate. The manifest snapshot hash covers the same fixed data described by the report. Return `{id,created_at,html_url,manifest_url}`. getExport(id) returns `{manifest,html,summary}`. All exported modes plainly labeled. Existing 0.1 exports remain untouched.

## Workflow interface

`server/workflows.ts` exports `createWorkflows({db,context,getFindingRevision,getCapture})` where context=()=>review.bootstrap(). Return `{bootstrap,saveReconciliation,saveDraft,draftHistory,snapshot}`. bootstrap() returns `{reconciliations,drafts,reconciliation_summary}`; snapshot includes revisions belonging to selected workflow records as well.

`saveReconciliation({entry_id?,previous_revision_id?,category,period_start,period_end,element_ids,quantity,unit,source,basis,measurement_method,comparison_key,decision?,approver_name?,approval_reference?,record_reference?,denominator?})`. Category trade_reported/imagery_supported/unresolved/inspection/approved/certification/payment. Quantity number >=0 or null; every non-null quantity requires unit, source, basis, period and exact scope. inspection/refs may use null. Approved quantity requires approver_name and approval_reference and is explicitly a recorded manual approval, not app-verified authority. No automatic quantity measurement. Versions append. summary comparable reported vs supported only when unit, element set, period, method/comparison_key match and quantities known; otherwise delta null with explanation. Overlapping rows do not sum. Observation summary deduplicates by element across dates. Coverage is distinct. Any percent requires explicit positive denominator and supported method/unit/scope, otherwise null.

`saveDraft({draft_id?,previous_revision_id?,type,title,description,location,requested_action,proposed_assignee,finding_revision_ids,annotation_ids?})` type issue/rfi, exact finding/capture/annotation snapshots resolved and validated by server, append revisions. Return draft `{draft_id,revision_id,revision,type,title,description,location,requested_action,proposed_assignee,finding_revision_ids,evidence,created_at,external_submission_enabled:false}`. No external submission route. Selection belongs to same workspace/model version. Selected annotations must belong to selected revisions. Omitting annotation_ids selects all annotations; an explicit empty array selects none. The complete source finding is always preserved alongside the selected overlays. draftHistory(id) returns revisions.

`snapshot({reconciliation_entry_ids?,draft_ids?}?)` validates exact current IDs, includes selected records and their full revision histories, and recomputes the reconciliation summary from that selection. An omitted list includes all current records; an explicit empty array includes none. Selection does not filter finding/task/source or historical scope histories.

## HTTP contract and UI

All `/api/v2/:workspace/*` require existing local session; all mutations CSRF protected. GET bootstrap merges review.bootstrap(), workflow.bootstrap(), coverage. POST configure; POST findings; GET findings/:id/history; POST tasks; POST tasks/evidence; GET coverage?as_of_date=&freshness_days=; GET reconciliation?period_start=&period_end= returns a period-filtered workflow summary; POST photos (22MiB JSON envelope); GET media/:id; GET media/:id/display; GET /api/v2/fixture/demo-source; POST reconciliation; POST drafts; GET drafts/:id/history; POST exports `{reconciliation_entry_ids?,draft_ids?,coverage_rule?}`; GET exports/:id/report|manifest (`?inline=1` opens the HTML report for inspection). Generic JSON remains 64KiB. Each mutation returns created record; UI reloads bootstrap. Unsupported/live workspace is rejected.

`src/ReviewWorkbench.tsx` default component props `{csrfToken:string,initialWorkspace?:"fixture"|"local",onOpenPackets?:(workspace:"fixture"|"local")=>void,onContextChange?:(context:{workspace:string,project_name:string,reviewer_name:string})=>void}`. It owns separate API v2 UI and `src/workbench.css`; App.tsx shell integration is root-owned. Sections: element review with image annotation rectangles and mixed results/history; recapture tasks and coverage; photo import/configuration; reconciliation; editable local drafts; fixed packet export. `src/ReviewRegister.tsx` connects the top-level Review log and Evidence packets to both review workspaces. It distinguishes current capture–element findings, distinct reviewed elements, captures with element review, element revisions and preserved scope records. Evidence packets selects workflow records and explicitly records coverage freshness/as-of inputs. Existing styles/white header/light sidebar/blue actions remain. Clearly label Synthetic demo versus Local photographs (manual BIM references, no APS model). Show original date precision and separate upload date. No calculated install claim from counts.
